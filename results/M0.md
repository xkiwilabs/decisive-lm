## Config facts

| Sliding window W | **512** | **1024** |
| KV sharing | last 18 layers reuse K/V of the last earlier layer of the same type | none |
| Per-Layer Embeddings | yes, 256 per layer, vocab-sized (262,144) | none |
| Hidden size (scorer input) | 2560 | 2816 |
| Attention | 8 heads, 2 KV heads, head dim 256 (512 on full layers) | 16 heads, 8 KV heads; full layers K = V, 2 KV heads, head dim 512 |
| MoE | no | 128 experts, top 8 |
| Image tokens | causal, like text | bidirectional within an image, **sliding layers only** |
| Image soft tokens | `max_soft_tokens` ∈ {70, 140, 280, 560, 1120}, default 280 | same |
| Audio | yes | no |

**Masks.** `Gemma4TextModel.forward` and `Gemma4Model.forward` both accept
`attention_mask` as a `{"full_attention": ..., "sliding_attention": ...}` dict and
pass it through unchanged, together with custom `position_ids`. Neither the SDPA
nor the eager path applies the window by itself (`sliding_window` is passed to the
attention function but SDPA ignores it), so the explicit masks are what decide.
`decisivelm/tree.py` builds both from the tree with logical positions and returns
additive float masks, which work for SDPA and eager alike.

**KV sharing (E4B).** A shared layer reuses the K/V tensors of the last
non-shared layer of the same type, position by position, and applies its own
layer type's mask. Tree masks therefore stay correct; the tiny dense config has
KV sharing on to test this.

**Bidirectional image attention (26B A4B).** With
`use_bidirectional_attention="vision"`, Gemma 4 lets tokens of one image attend
to each other on sliding layers, and keeps global layers causal. Unlike Gemma 3,
which did this on all layers. When we pass our own mask dict this is skipped, so
`tree.py` adds it: `attention_masks(..., bidirectional_images=True)` lets the soft tokens of one image see each
other on sliding layers, inside the window (2026-10-10; real-model check below).

## Query tokens

| Type | id | token |
|---|---|---|
| Choice | 6 | `<unused0>` |
| Score | 7 | `<unused1>` |
| Noul | 8 | `<unused2>` |

The vocabulary has 6,230 `<unusedN>` ids. The tokenizer never emits these three,
even for the literal string `<unused0>`, which splits into ordinary pieces; they
can only enter through `input_ids`, which is how the packer inserts them. Their
embedding rows are not zero (norms ≈ 1.04 against a vocabulary median of 1.22),
which doesn't matter because those rows are trained. They also have PLE rows,
which stay frozen.

## Mask equivalence on the real model (fp32, MPS)

Tree: one 448×448 image (256 soft tokens) plus 700 text tokens, a 965-token
prefix (W = 512); one Choice question with a 40-token segment and three leaves of
191, 231 and 161 tokens (583 > W); one Noul leaf of 61 tokens. Every leaf token's
hidden state from the packed pass was compared with running its root-to-leaf path
alone through the stock model with the stock masks.

- worst relative error over leaf states: **5.2e-6**; over query-token states: **6.3e-6** (threshold 1e-3)
- fp32 shifted-packing check: 9.3e-6

## bf16 noise floor

Same 6-leaf request; query-token hidden states compared.

| Comparison | MPS bf16 | CPU bf16 | MPS fp32 |
|---|---|---|---|
| identical input, repeated | 0 | — | — |
| request packed after another (offset 258) | 6.2e-2 (min cosine .9975) | 1.3e-1 (min cosine .9908) | 9.3e-6 |
| leaves in reverse packing order | 2.7e-2 | — | — |
| packed vs path run alone | 3.6e-2 | 2.3e-2 | 1.0e-5 |

This is numerical noise, not a packing bug (fp32 agrees to 1e-5), but it is
large: bf16 error accumulates over 42 layers. Consequences:

- The bf16 independence tolerance (3× the noise floor, docs/guide/11 §11.7) must be set
  on **probabilities** once the head exists (M1). On hidden states it would be loose.
- Worth testing at M1: running the scorer head in fp32, and fp32 or mixed-precision
  inference for the backbone. E4B in fp32 is ~32 GB, which fits on this Mac.
- Determinism holds for identical inputs at identical offsets.

## Latency (bf16, MPS, batch 1)

1,000-token text state, 4 Choice questions × 5 options (20 blocks), 1,240 packed
tokens: **p50 355 ms, p95 376 ms**, excluding mask construction. The latency
target (p50 ≤ 150 ms) is for the target CUDA GPU; this number is a Mac baseline
only.

## CUDA: E4B repeat and 26B A4B (GPU box, 2026-10-06)

**Run:** RTX PRO 6000 Blackwell Max-Q (sm_120), one card (GPU 0); 26B A4B's fp32 mask check in host RAM (`--fp32-device cpu`, 251 GB).
**Versions:** torch 2.14.1+cu130 (CUDA 13.0), transformers 5.18.0, Python 3.13, SDPA.
**Models:** E4B @ `ee0ef602`; 26B A4B @ `4d7ae4984b7db7de8f8457170b3f1a419ee76d52`. Logs: `data/m0_e4b_v2.log`, `data/m0_26b_v2.log`.

| | E4B | 26B A4B |
|---|---|---|
| Layers, W | 42 (35 sliding, 7 full), W = 512 | 30 (25 sliding, 5 full), W = 1024 |
| Query-token row norms (vocab median) | 1.038 / 1.035 / 1.044 (1.218) | 1.076 / 1.031 / 1.027 (1.559) |
| Mask check tree | 256 image + text, prefix 981, branches 580 | text only (bidirectional image attention not built), prefix 1436, branches 1158 |
| Masks, fp32 (leaf / query) | 8.1e-6 / 6.9e-6 PASS | 3.2e-5 / 1.3e-5 PASS, expert selection forced |
| Free routing, fp32 (leaf / query) | — | 1.5e-2 / 9.9e-2, first flip at layer 15 |
| bf16: packed after another request (offset 258) | 4.5e-2 | 2.4e-1 |
| bf16: leaves in reverse order | 2.7e-2 | 1.4e-1 |
| Latency, 1,240 tokens, 20 blocks, batch 1, bf16 | p50 75 ms, p95 75 ms | p50 139 ms, p95 140 ms |

E4B on CUDA matches the Mac run. Both backbones meet the latency target (p50 ≤ 150 ms); 26B only just.

**26B A4B: why the mask check forces routing.** Each token picks its top 8 of 128 experts. A packed pass and a path run alone sum in different orders, so fp32 hidden states differ by ~1e-6. Where two expert scores are nearly tied, that flips the selection, and the flipped token's state jumps. The jump then spreads to every later token that attends to it. Run as written, the check failed (1.5e-2 / 9.9e-2 against 1e-3). `m0_real.py` therefore records each token's selection in the packed run and imposes it, for the matching tokens, on each path run alone; the weights still come from the alone run's own router probabilities. Per leaf, packed vs alone:

| Leaf | Free routing (leaf / query) | Selection forced (leaf / query) | First layer with a flip |
|---|---|---|---|
| Q1 option 1 (379 tokens) | 3.3e-4 / 3.9e-5 | 2.9e-5 / 5.1e-6 | 17 |
| Q1 option 2 (461 tokens) | 1.5e-2 / 9.9e-2 | 2.2e-5 / 8.8e-6 | 15 |
| Q1 option 3 (318 tokens) | 7.7e-3 / 4.7e-4 | 3.2e-5 / 1.3e-5 | 17 |
| Noul (61 tokens) | 1.6e-4 / 7.0e-5 | 1.2e-5 / 5.4e-6 | 17 |

Per-layer error stays at 1e-7 to 1e-5 until the first layer where a token's top-8 set differs, and jumps there (option 2: 1e-5 → 2e-3 at layer 16). With selection forced it stays under 1e-4 at every layer. Masks and logical positions are therefore right at W = 1024, and routing is per token, so nothing leaks in exact arithmetic.

**Consequences.**
- Independence by construction holds on 26B A4B only up to routing noise. That noise is about 5× E4B's in bf16 (2.4e-1 vs 4.5e-2) and is not removed by fp32.
- At the probability level (P1 seed-0 heads, bf16, 200 gold_test questions; `results/invariance_P1_26b-a4b.md`, `results/invariance_P1_e4b_cuda.md`), repacking changes 19–22% of 26B answers (E4B: 3–4.5%), and 45–65% of the least-confident fifth (E4B: 7.5–10%).
- 26B tolerances (docs/guide/11 §11.7) have to come from those measurements.

## Images in the packed tree (2026-10-10)

`decisivelm/media.py` encodes each image at a fixed soft-token budget into `<|image>`, n × `<|image|>`, `<image|>`
(identical to Gemma 4's processor for a lone placeholder, tested), the packed tree carries the pixels in token order,
and `tree.attention_masks` adds 26B A4B's bidirectional image block on sliding layers.

- CI (tiny random Gemma4Model with a vision tower, fp32): two requests, three images at budgets 70 and 140, packed
  vs each path run alone through the stock model: worst relative error 3e-6 on both variants. Swapping two images'
  pixels gives 5e-1; dropping the bidirectional block on the 26B-like variant fails (> 1e-2).
- Real model, 26B A4B, fp32 on CPU (`scripts/m0_real.py --backbone 26b-a4b --device cpu`): prefix 1,698 tokens with
  one 448×448 image (256 soft tokens, bidirectional on sliding layers) > W = 1,024; question-1 branches 1,158 > W.
  With expert selection forced to the packed run's: worst leaf 5.5e-5, query 3.2e-5 (threshold 1e-3): **pass**.
  Free routing (noise): worst leaf 6.2e-3, first flip at layer 18.
